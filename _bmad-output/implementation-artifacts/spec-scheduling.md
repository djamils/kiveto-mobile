## Intent

**Problem:** The owner cannot book, see, move or cancel an appointment: « Prendre rendez-vous » (home) and the Rendez-vous tab lead to placeholders, although the Portal API serves the whole booking flow (motifs, practitioners, a 14-day availability window, booking for a known or a new pet with an `Idempotency-Key`, the appointment lists, reschedule, cancel, `.ics`).

**Approach:** Build `lib/features/scheduling` on the D15 layout over `SchedulingApi`: a pure-Dart `BookingDraft` (the wizard's intent and its `IdempotencyKey`, a new key whenever the content changes) held by one wizard notifier across four full-screen routes 12 → 13 → 3 → 14; screen 4 with cursor-paginated upcoming/past tabs; the cancellation as a sheet over 4 (16); reschedule reusing screen 3's slot picker; « Ajouter à mon calendrier » handing the `.ics` to the OS share sheet (`share_plus`). The clinic's phone and address come from `GET /me` (backend branch `feature/portal-me-clinic-contact`, contract synced in `3bd69e2`). Mockups 12/13/03/14/04/16 decide the look, the contract decides the data; undesigned states use the kit.

## Boundaries & Constraints

**Always:**
- D15 rules 1–8 (`test/architecture/`). Feature graph: scheduling → client, patient (public APIs only); home → scheduling (home composes it; no cycle: patient, client, document never import scheduling). Scheduling's domain/application import no other feature (a pet id is a plain `String` there). 100 % line coverage, file by file, of every new or changed file of `features/*/{domain,application,infrastructure}` and `shared/domain`; `make ci` green.
- material_ui only (`package:material_ui/material_ui.dart`); Dart 3.13 constructors (`const new(...)`); repositories throw `ApiFailure`; no `print`, no `DateTime.now()` in domain/application (inject the `Clock`; presentation uses `clockProvider`); no `dynamic` at API boundaries; never `copyWith(fontSize:)` (use `kivetoTextStyle`).
- French user strings only in `lib/l10n/app_fr.arb` (keys prefixed `booking…`, `appointments…`, `appointmentCancel…`, `reschedule…`, each with `@key.description`, ICU for plurals/placeholders), then `fvm flutter gen-l10n`. Code, comments, docs in English.
- Clinic-scoped providers `ref.watch(sessionStatusProvider)` and watch only the active clinic id (`activeClinicProvider.selectAsync((c) => c?.clinicId)`); read providers through `AsyncData` patterns / `AsyncValueView`, never `.value`; unwrap Riverpod's `ProviderException` before switching on a failure type.
- Page exits are `void Function(BuildContext …)` callbacks wired in `lib/app/routing/app_router.dart` (features never import `app/`).
- A booking `startAt` is never built from a UTC `DateTime`: the slot is the domain `ClinicInstant` mapped from the availability answer, and infrastructure sends it back as `OffsetDateTime.from(slot.instant, offset: slot.offset)` (wire `2026-11-09T10:00:00+01:00`, no fraction, no `Z`); test the encoded request body.
- One `IdempotencyKey` per booking intent: the same key on every retry of the same content (network failure, refresh replay), a new key as soon as the clinic, the pet (or the new pet's name/species), the motif, the practitioner or the slot changes.
- The server decides: which slots exist, the confirmation mode, the cancellation window (`cancellableUntil`), whether a pet is bookable. The app only shows bookable slots received, shows « Reporter »/« Annuler » while `now < cancellableUntil`, and shows « Reporter » only for `source == portal` with a motif id (the API refuses any other reschedule with `booking_not_open`).
- After a successful booking, reschedule or cancellation: bump `appointmentsRevisionProvider` (scheduling public API) — the appointments lists and the home (`homeOverviewProvider` watches it) reload — and invalidate patient's `careItemsProvider` (the « RDV pris » pill); after a booking with a new pet also invalidate patient's `petsProvider`.
- Dependency `share_plus: 13.3.1` (checked 2026-11-03 on pub.dev: latest, published 2026-10-01 by fluttercommunity.dev, Flutter Favorite, Dart ≥ 3.10 / Flutter ≥ 3.38.1; `fvm flutter pub add --dry-run share_plus:13.3.1` resolves, adding share_plus_platform_interface 7.2.0 and cross_file 0.3.5+5) pinned exactly with a pubspec comment in the style of the others, and recorded in architecture.md §5 (row « Share sheet »). Why: Android has no `text/calendar` VIEW handler on the emulator (Google Calendar does not import `.ics`), the ACTION_SEND share sheet does (Drive, Gmail, Messages, Bluetooth) and iOS's share sheet offers « Ajouter au calendrier ».

**Never:**
- Edit `packages/kiveto_portal_api/`, `contracts/`, `CLAUDE.md`, `.claude/settings.json`; import `package:flutter/material.dart` or `cupertino.dart`.
- Re-implement backend rules (no client-side slot computation, no cancellation-delay arithmetic, no « premier disponible » resolution: the API has no such practitioner).
- Build screen 15 (the questionnaire stays the placeholder route `/appointments/:id/questionnaire`), the new-client booking requests of 4 (`GET /me/booking-requests`, slice 7), notifications, iOS specifics.
- Promise an SMS for a `pending_clinic_confirmation` booking.

## Design Notes

**Wizard lifetime.** Four routes on the root navigator, each watching `bookingWizardProvider` (autoDispose): it lives while any booking page is mounted and dies when the last one pops (X, the success exits). The draft is dropped (fresh state, new key) when the session or the active clinic id changes — not while `/me` reloads (watch the id through `selectAsync`/a record of `AsyncData`, never `.value`).

**Slot picker.** Window = 14 days from `deviceToday(clock)` (deferred-work: device vs clinic date; one retry with `from + 1` on a `from` violation). Pages of 7 consecutive days starting at the window start (not Monday-aligned: earlier days cannot be requested), 7 columns (the mockup's 6 Mon–Sat columns would hide Sundays the API returns; deviation recorded). Week 2 comes from the same answer; week 3 requests the next window (`from + 14 … from + 27`); « next » is disabled when every day of the last window read is closed (beyond the horizon). Month label from the visible days (« Novembre 2026 », « Novembre – décembre 2026 »). Day cell: weekday « Lun » 11/600 + number 18/700, min-height 60, radius 10: selected brand fill, open white + `border`, closed `KivetoDashedBorder(color: borderChip)` on canvas, ink subtle, not tappable. Periods « Matin » (clinic hour < 12) / « Après-midi », hidden when empty; slots 4 columns, gap 8, min-height 44, radius 10, 14/600; selected brand, free white + `borderStrong`, taken = `draft.takenSlots` of that day absent from the fresh answer, struck, canvas, not tappable.
